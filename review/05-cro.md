# 05 · 转化漏斗专项（CRO）

专项：从「首屏输入框」到「Creem 付款成功」再到「Pro 用户能真正用起来」的全程摩擦点。

## 0. 方法与证据边界（先读）

- **纯静态取证**：全部结论来自源码阅读，带 `文件:行号`。本轮没有跑浏览器、没有跑线上审计——因为终点（付款）不可能在没有真实卡的情况下验证。
- **凡是"用户会怎么想"的判断，一律标【赌注】**，并给一个零流量下也能做的验证动作。
- **凡是"拉不到数据"的地方，我写清楚为什么拉不到**，不拿代码结构冒充行为数据。
- 零流量（14 pv / 11 天）意味着：**任何改动的效果都无法用本站数据验收**。所以本报告给的是**可计数的不变量**（"结果页首个 CTA 之前必须出现待办摘要"），不是"改了会涨"。

### 0.1 先纠正一个前提：「90 天 0 次 upgrade_cta_clicked」不能当结论用

这条数字是真的，但它不是"用户不想买"的证据，甚至不是"没人点"的证据。它要同时穿过五道门才会被记录：

| 门 | 位置 | 说明 |
|---|---|---|
| 1 | 到达站点 | 14 pv / 11 天，且是 CF 口径的真人 |
| 2 | **接受 analytics** | `Layout.astro:73-79` `geoTrack` 只在 `typeof gtag === 'function'` 时上报；`public/scripts/consent.js:170-176` 里两个勾选框**默认不勾**，点 "Essential only" 或直接点 "Save choices" 都等于不上报 |
| 3 | 完成一次审计 | 需代理抓取成功（`src/lib/fetcher.js:70`，见 §2 断点 B） |
| 4 | 滚 ≈4–6 屏到 CTA | 见 §2 断点 D |
| 5 | 在遮罩解除后点中按钮 | 移动端 CTA 只露 8px（设计侧已证） |

> **口径修正（来自 `02-design-system.md` / design-system-architect 同步）**：本报告里凡是"首屏有 CTA"的表述，成立条件必须限定为 `html[data-consent="decided"]`。真实首访（`pending`）下，390×844 的 `#audit-btn` 被 `Layout.astro:274` 的 `fixed bottom-0` 面板压住，只露 8px；`10-08` 那份"CTA 首屏可见 ✅"测的是已决策态。所以 §1 漏斗图的第一段对绝大多数真实流量是**关闭**的——后面的每一项断点，都建立在"用户已经越过这一关"之上。

**测算**：14 次会话 × 同意率 ~0.4 × 审计成功率 ~0.6 × 到达 CTA 位置 ~0.5 ≈ **1.7 次可被记录的点击期望值**。观测到 0，完全在噪声内。

> 所以：`0 次升级`是**"没人走到那儿"的弱证据**，不是**"走到那儿也不买"的证据**。本报告后面的断点全部**不依赖这条数字成立**——它们是结构事实（代码里没有那个元素 / 那个顺序 / 那个入口），谁都能复核。

## 2. 摩擦点清单（按影响排序）

排序原则：**先排"阻断唯一收入路径"的，再排"降低转化意愿"的，最后排"降低体验"的。**

---

### P0-1 结果页没有"下一步"，而付款请求排在待办清单之前

**事实（不是判断）**：`boot.js:395-408` 的 12 个区块里，`renderUpgradeCta(r,'primary')` 是第 5 个（`:400`），`renderFixesPanel(r.recommendations)` 是第 9 个（`:404`）。也就是说：**用户在被要求付费之后，才看到"我该修什么"**。

`reportHeader.js:11-31` 整个分数头里没有任何动作元素：没有"下一步"，没有"首要问题"，没有"再跑一次"。只有 `score / level / timestamp / summary`。

94 分会发生什么（`upgradeCta.js:57-63`，`bucket('high')`）：

> 标题："94 means the basics have no obvious problems"
> 正文："The score alone cannot prove an AI answer will mention your site. Pro includes a content-based AI visibility simulation."
> 按钮："See what Pro includes" → `/pricing/`

这段文案的逻辑是：**"你很好 → 但你无法证明你好 → 所以买"**。它没有告诉用户"你的站此刻最该动的一件事是什么"。而事实上报告里有：`recommendations` 已经算出低优先级项（`recommendations.js:19-33`），只是排在下面 4 屏。

同样的错位出现在低分桶：`upgradeCta.js:31-33` 标题写"你的站这次有 N 项优先修复项"——这个数字是用户最想知道的东西，但它离真正的清单隔了 4 个区块，且旁边按钮是"持续跟踪这个站"（`upgradeCta.js:43`），不是"跳到那 N 项"。

**影响**：这是唯一一条"用户已经产生意图（跑完了）却拿不到指令"的路径。首屏遮挡（断点 A）决定有没有人进来，这一条决定进来的人有没有下一步。

**验证**：不需要流量。改之前先做一件零成本的事——把 `boot.js:395-408` 的顺序念给 5 个人听（"分数→雷达→11维→负面信号→买 Pro→SEO→修复文件→留邮箱→修复清单"），问他们"第 4 步之后你想点什么"。如果 5 个人里有 3 个说"我想看我该修什么"，这条就被证实了。【赌注】

### P0-2 审完一次就再也审不了第二次——同 URL 趋势图是死代码

**事实 1**：`boot.js:212` 在开始审计的瞬间 `geoHide(document.getElementById("hero-section"))`，把 hero（含 `#url-input` 和 `#audit-btn`）隐藏。全文再没有任何地方把它显示回来（`geoShow` 只在 `:283` 定义，无处调用）。

→ **点过一次 Start Audit 之后，这个页面就永久失去输入框**。想审第二个站必须刷新整页。

**事实 2**：`boot.js:434-436` 只有在 `getUrlHistory(r.url).length >= 2` 时才插入趋势图。而 `src/lib/history.js:22-24`：

```js
var existing = history.findIndex(function(e) { return e.url === entry.url; });
if (existing >= 0) history.splice(existing, 1);   // 同 URL 先删旧、再插新
```

历史按 URL **去重**，每个 URL 永远只剩 1 条。因此 `getUrlHistory()` 的返回值长度**恒为 1**，`>= 2` 永远不成立，**趋势图在正常使用下永远不渲染**。

**事实 3**：`#compare-link` 在 `boot.js:264-266` 需要 `history.length >= 2`（两个不同 URL）才显示；同样因为事实 1，**单次会话内拿不到两个 URL**，只能靠跨会话的历史残留。

**影响**：这三件事拼起来，正好拆掉了这个产品的留存机制——

- 「定期回来看分数有没有变」是 Pro 要卖的东西（`pricing.astro:77`），但免费端连"同一个站跑两次"都做不到；
- 「改完修复文件 → 再跑一次验证」是这个工具唯一能自我证明价值的回路，而这个回路在代码里不存在；
- 趋势图是"分数会变"这个概念的视觉证明，现在是死代码，等于 0 成本地丢掉了一个说服资产。

**这条是全场最便宜的修复**：把 `history.js:22` 的去重改成"同 URL 保留最近 N 条"（或 key 改成 `url + timestamp`），趋势图立刻活；再把 hero 在报告底部恢复一次（或在 `renderFixesPanel` 下面加一个"审计另一个站"的输入框），compare 和二次审计同时活。

### P0-3 付款成功之后什么都没有——已付费用户空转

**事实**：`pricing.astro:270-282` 对 `?checkout=success` 的全部处理，只是发一个 `checkout_returned` 埋点。**没有成功态 UI**。用户付完钱回到 `/pricing/`，看到的还是那张报价表，还是那两个按钮（`$9/mo` / `$79/yr`），没有任何"你已经是 Pro"的迹象。

**事实**：Pro 的功能面板只挂在首页 `index.astro:171-196`（`#pro-monitor-root`），且 `boot.js:740-766` 要求已登录才 `remove('hidden')`。而全站导航里**没有任何一处链接指向它**：`auth.js:333` 登录后下拉菜单的选项只有「Upgrade Plan → /pricing/」和「Sign Out」——**已经是 Pro 的用户看到的仍然是 "Upgrade Plan"**。

**事实**：Pro 的 PDF 导出按钮（`auditHistory.js:68`）只出现在云端历史行上。新付费用户的历史是空的（要等第一次 cron 跑完，`pro.js:641` 周更），所以在付费后最长一周内，「PDF export」这个卖点是**字面意义上不可用的**。

**影响**：这是退款和差评的直接来源，也是复购的前提。用户在付完钱的最有动力的那 60 秒里，得到一个"什么都没发生"的页面。

**验证**：不需要流量。拿一个测试账号走一遍真实付款（或直接手动写 `subscriptions` 表模拟），看回到 `/pricing/?checkout=success` 之后能否在**不查文档**的情况下找到自己的监控面板。走一遍就知道。

### P0-4 未登录点价格 → 登录 → 必须再点一次

**事实**：`pricing.astro:224-232`：

```js
const token = localStorage.getItem('geoscore_token');
if (!token) {
  if (window.geoscoreAuth) window.geoscoreAuth.openAuthModal();
  else showToast('Please sign in first to start your free trial.', 'info');
  return;                      // ← 直接 return，没有记住"用户想买哪个周期"
}
```

`auth.js:220-222 / 269-271` 登录成功后只做 `closeAuthModal()`，没有任何 pending-checkout 的续接逻辑（全仓 `grep pending|resume|intent` 无命中）。

**后果链**：点 $9 → 弹框 → 输邮箱 → 等验证码 → 输 6 位码 → 弹框关闭 → **回到原样**。用户此刻看到的唯一变化是右上角从 "Sign In" 变成了自己的头像。他必须自己想明白"现在可以再点一次了"。

**影响**：这是标准漏斗里掉得最狠的一步（账号创建 + 邮箱往返），而且我们把它做成了**两次点击 + 一次无解释的中断**。`pricing.astro:229` 那句 `showToast('Please sign in first...')` 只会在 `geoscoreAuth` 未加载时出现（正常情况下永远不会显示），所以用户连"我为什么要登录"都没被告知。

**顺带**：`FAQ`（`pricing.astro:176`）说"7-day free trial，试用结束后才扣款"——意味着**要绑卡**。对 $9 的冲动型购买，"先注册再绑卡"是两个连续的阻力，中间没有任何价值演示。

### P1-5 免费层已经把"一次性价值"给完了，Pro 卖的全是"延迟价值"

这一条是 §3 的结论先行版，细节在 §3。核心事实：`pricing.astro:60-66` 与 `:76-82` 两列对比，**Free 已经包含** 11 维 / 85+ 检查 / 修复文件生成 / CLI & MCP —— 也就是这个工具**全部一次性的、当场可感知的价值**。Pro 的 7 条（`:76-82`）里：

| Pro 卖点 | 是否独有 | 付款后 60 秒内能否体验 |
|---|---|---|
| Everything in Free | — | — |
| Weekly automated audits | ✅ 独有 | ❌ 要等下周 |
| 30-day audit history | ⚠️ 免费端有本地历史（50 条，`history.js:25`） | ❌ 要等有第二条记录 |
| Regression alerts | ✅ 独有 | ❌ 要等分数掉 ≥10（`pro.js:16`） |
| PDF export | ⚠️ 免费端已给 MD/HTML/JSON/CSV（`exportButtons.js:3-8`） | ⚠️ 需先有云端记录 |
| AI visibility estimate | ⚠️ 免费端其实有 1 次/月（见下） | ❌ UI 只挂在 Pro 面板里 |
| 5 domains | ✅ 独有 | ❌ 只有一个站的人此刻不需要 |

**7 条里 0 条是"现在就能感受到的"**。这不是价格问题，是**时序问题**：用户付钱买的是"未来会发生的事"，而此刻没有任何东西改变。

**关于 AI visibility 那条，有一个更麻烦的事实**：`upgradeCta.js:50-51 / 59-60` 两处文案都在卖"Pro 提供 AI 可见性模拟"。但服务端 `worker/freeVisibility.js` 已经实现了**免费层也能跑**（`FREE_ENGINES = ['chatgpt']`，1 次/自然月，`visibilityQuota.js:18`）。

- 好消息：这不是虚假宣传（免费 1 引擎 vs Pro 4 引擎，确实是差异）；
- 坏消息：**这个免费能力在前端没有任何入口**。`openVisibility()` 只被 `sitesPanel.js:74` 调用，而 `sitesPanel` 只在 Pro 面板里初始化（`boot.js:753-756`）。所以 **`/api/visibility/check` 的免费分支是一段没有 UI 的后端代码**。
- 更坏的消息：`pricing.astro:81` 自己在卖点末尾加了"not real engine traffic"的免责说明——**用一句话把刚卖出去的卖点打折了**。

即：我们有一个能立刻产生"啊，原来 AI 真的不引用我"这种 aha 的能力，把它锁在付费墙后，同时在付费墙上写着"这个数据其实不真实"。

### P1-6 定价页：Pro 卡没有价格位，另一半卡位不可购买

**事实 A（价格位）**：四张卡的价格行结构不一致——

- Free：`<div class="text-3xl font-extrabold mb-1">$0</div>` + `forever`（`pricing.astro:58-59`）
- **Pro：`<div class="text-xs text-gray-500 mb-6">Taxes included</div>`（`:74`）——价格行没有价格**
- Studio：`$29/mo` 大字（`:101`）
- Agency：`$59/mo` 大字（`:118`）

Pro 的 $9 只出现在底部两个小按钮里（`:86-94`）。眼睛扫价格时会看到 `$0 / （空） / $29 / $59`，**唯一想卖的那张卡在价格位上最弱**。

**事实 B（卡位）**：`md:grid-cols-4`（`:54`）意味着桌面端四列并排，**一半的格子是 `opacity-50 cursor-not-allowed` 的 Coming Soon**（`:98-129`）。移动端四张卡竖排，Pro 是第 2 屏。

**事实 B2（768 档挤压，design-system-architect 同步）**：`md:` 断点在 768px 就生效，四列均分后卡内容宽约 114px；Pro 卡内部再切两列价格按钮（`:85` `grid-cols-2`），每个约 45px，而 `$79/yr` 按 18px 渲染约需 52px → **平板档溢出/换行**。768–1024 恰好是"iPad 竖屏 / 小笔记本"，也是 B2B 决策者最常用的试看档位，不是可以忽略的中间态。

**事实 C（年付按钮）**：`:90-93` 的 `$79/yr` 按钮副标是 "Save $29"，**没有写"无试用"**；而 FAQ `:176` 明确写年付不打折试用、立即扣款。用户在最需要知道的地方（按钮上）看不到这条，只会在付款页面上被"惊喜"。

**判断（【赌注】）**：两张 Coming Soon 卡对 $9 的实际作用不是"把价格锚高"（那是 $59 的作用，而且 `opacity-50` 已经把它废了），而是**传递"这是个还没做完的产品"**。对一个 $9 冲动购买，这个信号的代价大于锚定收益。

**验证**：给 5 个人看定价页截图 10 秒，问两个问题——"Pro 多少钱？"（测价格位）和"这个产品上线了吗？"（测 Coming Soon 的副作用）。两个问题都有唯一正确答案，答错率就是这条的证据。

### P1-7 唯一"可带走"的资产是一个 404

**事实**：`shareButtons.js:50` 生成嵌入代码：

```html
<a href="https://geoscore.help/?audit=<url>"><img src="https://geoscore.help/badge/<url>" ...></a>
```

全仓、`dist/`、`worker/pro.js:136-149` 的路由表里**都没有 `/badge/` 这个端点**（`dist/` 下不存在 `badge` 目录）。用户照着做，页面上是一个碎图。

**事实**：分享区在报告第 11/12 位（`boot.js:406`），在所有修复建议、导出按钮之后——**最不可能被看到的位置**。而"晒分数"是这个产品唯一自带的传播回路。

**事实**：`?audit=` 自动跑审计是好的死循环修复（`boot.js:677-687` 会自动 `startAudit`），所以分享**链接**本身可用；坏的只是**图片**。

**影响**：一个 embed badge 是长期外链资产（每个嵌入都是一个 dofollow/at least 品牌曝光）。现在是 404，等于把唯一一个"用户主动帮我们发外链"的入口做成了负体验。

**修复成本**：极低（一个 SVG 响应 + 缓存头）。**证据档：A**（存在即可验证：`curl /badge/example.com` 返回 200 + image/svg+xml）。

### P2-8 失败态是死胡同，且文案带术语

**事实**：`boot.js:274` 抓取失败时，把整块 loading 卡片替换成：

> Audit Failed / `<err.message>` / [Try Again]

三个问题：

1. **`err.message` 直接透出**（`scanner.js:64-66`）："Could not fetch https://…. The site may be blocking cross-origin requests or is offline." —— 对一个 SaaS 创始人，"cross-origin requests" 不是他能处理的信息，正确信息应该是"你的站可能开了 Cloudflare 的 Bot Fight / WAF，把我们的抓取代理挡住了"。
2. **只能重试同一个 URL**：hero 已被隐藏（`:212`），`#audit-retry` 调 `startAudit(entryPoint)` 用的还是 `#url-input` 里的旧值。**用户连打错的字都改不了**。
3. **失败的人不会被留下任何东西**：没有"留个邮箱，能抓了/修好了通知你"。而这个失败点恰恰是**意图最强**的时刻（他刚认真输入了自己的域名）。

**频率是【赌注】**（没有数据能测被抓取失败率）。但结构上可以确定：`fetcher.js:70` 对 4xx 直接 `return null` 且不区分 403（被 WAF 挡）和 404（打错地址），所以两类完全不同的原因会得到同一句技术性错误。

### P2-9 工具页承诺"查一项"，交付"整站 11 维"（意图错配 + 整页跳转）

**事实**：`/tools/llms-txt-checker/` 的按钮写 "Check Now"（`llms-txt-checker.astro:34`），`/tools/robots-txt-ai-checker/` 也是 "Check Now"（`:34`）。但这两个页面**没有 `#loading-section` / `#report-section`**，提交后 `boot.js:194-205` 直接整页跳到 `/?audit=…&src=tool_page&tool=…`。

用户来问的是一个是非题（"我有 llms.txt 吗"），拿到的是一份 11 维 94 分的体检报告。**他的答案藏在第 3 个区块的某一行的某个 `<span>` 里。**

**这解释了为什么工具页 619 展示 / 1 点击（关键词侧数据）之后没有转化**：不是流量不准，是**用户的问题在结果页第一屏没有得到回答**。【赌注】——展示→点击低是关键词侧的结论，我这里只负责"点击之后也没接住"这一段。

**对照**：`showAuditOrigin()`（`boot.js:633-650`）已经会显示"本次审计发起自 llms.txt Checker"，说明团队意识到来源丢失，但只是加了个标签，**没有把该工具的答案提到最前**。

### P3-11 结果页缺"基线"，94 分只能和其他 94 分比

**事实**：分数头（`reportHeader.js:11-31`）只有 `94 / Excellent / 时间戳 / 一句话 summary`。没有：

- **同类基线**（"你的 94 分在 324 个被审计网站里排前 X%"）——这个数据**仓库里就有**（`data/geo-audit-v2-final.csv`，324 样本、中位数 41、均值 43.4，见 `01-rate-authority.md` 已复算）。
- **社会证明**（用户数 / 案例 / 评价）——现在**一个都没有，也不该编**。
- **焦虑锚点**（"94 分 ≠ 会被引用"）——这条文案存在（`upgradeCta.js:59`），但它只是句断言，没有证据支撑。

**判断**：94 分用户看完的真实心理是"哦，我挺好"，然后关闭标签页。**"好"是最难转化的状态**——比 40 分难十倍，因为 40 分用户有痛感，94 分用户只有满足感。对 94 分唯一有效的驱动力是"你现在很好，但你的同行在 AI 回答里被提到，你没有"，而这需要**证据**，不是文案。

**这是【赌注】**：我不知道 94 分用户会不会焦虑。但我知道一件事——**如果 94 分真的很多（自家语料里 317/324 在 aiCrawlability 满分），那"94 分"本身就不值钱，值钱的是"你和 94 分的别人差别在哪"**。

## 3. 免费层与 Pro 的价值差判断

### 3.1 结论

**免费层没有"给太多"，而是"给错了种类"。**

它给的是一次性的**诊断价值**（分数 + 85 项检查 + 修复文件 + 4 种导出）——完整、慷慨、可以拿这个站去交付。它没给的、也正是 Pro 在卖的，是**持续价值**（每周跑、掉了告警、4 引擎、5 个站）。

问题在于：**一次性价值是可以被"用完就关"的，持续价值只有在"用起来之后"才有意义。** 一个刚跑完第一次审计的人，还没有任何理由需要"每周"——他连"下周会不会变"都还没怀疑过。

所以现在的结构是：

```
免费用户获得 100% 的诊断 → 关掉标签页 → 一周后完全忘记
Pro     卖的是"一周后的事" → 没人有动机买
```

**真正的缺口不是免费给多了，是"为什么需要持续"这件事没有被制造出来。**

### 3.2 逐条拆：贵的那 4 条其实都很弱

| Pro 卖点（`pricing.astro:76-82`） | 我的判断 | 依据 |
|---|---|---|
| Weekly automated audits | **唯一硬价值** | 这是免费做不到的（浏览器端审计，`scanner.js` 跑在用户浏览器，关页即停） |
| 30-day audit history | **半假差异** | 免费端已有本地历史 50 条、永不删除（`history.js:25`）。真正的差异只是"跨设备 + 云端"，对单人用户接近 0 |
| Regression alerts | 硬价值，但**条件概率极低** | `pro.js:16` 阈值 ≥10 分。一个 94 分的站一周掉 10 分的概率≈0，所以 94 分用户买它是买了个不会响的闹钟 |
| PDF export | **几乎无差异** | 免费已有 MD/HTML/JSON/CSV（`exportButtons.js`）。HTML 导出本身就"可打印成 PDF"。为这个付 $9 站不住 |
| AI visibility estimate | **最有说服力，但被自己拆台** | 免费端服务端已有（1 引擎/月），前端无入口；`pricing.astro:81` 自己写 "not real engine traffic" |
| 5 domains | 现在无意义 | 目标用户（一个人一个站）此刻不需要 |

**净结论**：真正不可替代的只有 **"每周自动跑 + 掉了告警"**。这是一个"保险"型产品，而保险的转化前提是**用户先相信风险存在**。我们没有任何一步在制造这个相信。

### 3.3 谁真的会付 $9

诚实地说：**一个 94 分、14 pv/11 天的站，不该买 Pro。** 它没有风险可保。真正会付 $9 的人是：

1. 有商业流量、且**已经被 AI 抢走流量**的站（他能感觉到）；
2. 给客户交付的**代理商/自由职业者**（他需要每周报告当交付物——但这正是 Studio 的定位，见 §P1-6）；
3. 同时在维护 2 个以上站的人（5 domains 才有意义）。

**这解释了 0 转化的一部分**：不是页面做得差，是**当前来的人不是买家**。14 pv 里大概 0 个属于上面三类。

这不是"不用改 CRO"的理由——恰恰相反：在没有人来的阶段，唯一值得做的 CRO 是**把 aha 提前到免费端**，让偶然来的人产生"我可能需要持续盯"的念头，而不是把力气花在按钮颜色上。

### 3.4 我认为正确的价值切分（判断，非执行）

| 层 | 应该给什么 | 为什么 |
|---|---|---|
| 免费·一次 | 11 维 + 修复文件 + 全部导出 + **1 次完整的 4 引擎可见性模拟**（去掉 Google 账号限制、去掉 IP/host 冷却到 1 次/月/站） | 让 aha 发生在付费墙**之前**。"AI 没有引用我"这个事实，比任何文案都有说服力 |
| 免费·可重复 | 同 URL 两次审计 + 趋势图（修 §P0-2） | 制造"分数会变"的认知，这是 Pro 的**概念预演** |
| Pro $9 | 每周自动 + 掉分告警 + 4 引擎每周追踪 + 云端历史 | 从"诊断"变成"看守"。价值主张一句话："你睡觉时它也在跑" |
| 不给 | PDF（免费也给）、30 天历史（本地已够） | 这不是差异化，是噪声，占了两行 bullet 的名额 |

> 注：把免费可见性从 "1 引擎/月/Google 账号" 放宽到 "4 引擎/月/任意账号" 会增加 LLM 成本（`worker/guardrails.js` 有全局月预算熔断）。在 14 pv 的现状下，这个成本可以忽略；等有量了再用预算闸门收。**这是【赌注】**，可逆：一个环境变量就能收回。
