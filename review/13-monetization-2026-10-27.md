## 0. 结论摘要（先给答案）

**漏斗卡点定位：卡在第一段「没人来」，不是后面三段。**

用一句话说：GeoScore 的**转化效率已经达到行业基准**（访客→付费 0.40%，基准 0.5%），
但**流量规模差 135–170 倍**（当前 83 会话/月，$500 MRR 需 11,200–14,000 会话/月）。
在「没人来」这个量级上，讨论「来了不试 / 试了不买」是浪费时间。

三个次生卡点，按严重度排序：

1. **Google 自然搜索等于零**：1219 展示 / 2 点击 / 均排 69.1。位置 51+ 的预期 CTR 是 0.01%–0.10%，
   实测 0.16% 已经**高于**曲线上沿 → 不是标题和 meta 写得差，是根本没有排名。
2. **免费工具不留痕**：leads = 0。免费审计不强制登录（"Sign-in optional"），
   249 会话跑完 21 次审计，一个邮箱都没留下 → 无法再营销、无法归因、无法培育。
3. **变现档位自缚手脚**：Studio $29 / Agency $59 全是 "Coming Soon"，把 ARPU 天花板锁死在 $9；
   而 $49 一次性服务走 Fiverr 站外成交，GA4 完全看不到，形成归因盲区。

**推荐路径：激进（done-for-you 服务先行）**，用 $49/$129 一次性服务在 14 天内产生现金，
同时用「免费诊断」表单把 leads 从 0 变成可培育资产。
订阅（保守路径）在当期流量下需要 135–170 倍增长才能到 $500 MRR，14 天内不可验证。

### 1.3 卡点判定（回答题眼）

| 候选卡点 | 是否成立 | 证据 |
|---|---|---|
| **没人来** | ✅ **决定性卡点** | 83 会话/月。$500 MRR @ $9 需 56 个订阅 → 按实测 0.40% 需 14,000 会话/月（**168×**）；按基准 0.5% 需 11,200/月（**135×**）。Google 自然搜索 90 天只贡献 2 次点击 |
| 来了不试 | ❌ 不成立 | 会话→audit_started 8.43%，基准 12.8%，同量级（略低但不是断点） |
| 试了不买 | ❌ 不成立 | 会话→付费 0.40%，基准 0.5%。**转化效率正常** |
| **试了不留痕** | ✅ **真实第四段卡点** | leads = 0。免费审计 sign-in optional，21 次审计不留 1 个邮箱。这是「试了不买」的更准确表述 |
| 买了不可持续 | ⚠️ **无法判定** | n=1，无留存数据、无续费数据；且该 1 笔是否真实扣款**从未核验**（Creem 后台未查）。不能下结论 |

**一句话定位**：漏斗不是「漏」，是「源头只有一根吸管」。
真正的问题不是 0.16% 的 CTR，而是 CTR 分母只有 1219；
不是 8.43% 的试用率，而是试用基数只有 249。

### 1.4 一个必须先做、否则全盘皆虚的动作

**第 8 段的 0.40% 是用 n=1 算出来的，置信度极低。**
GA4 记 sign_in = 1，但数据库有 2 个用户 → GA4 存在漏计（可能是 consent banner、adblock、
或 app 子域未埋点）。因此那 1 个 pro 订阅**是否来自这个漏斗都无法确认**。

> 结论不因此改变：因为「83 会话/月」是硬事实，135–170 倍的差距不会因 n=1 的噪声而消失。
> 但**在埋点修好之前，任何 A/B 测试都是在噪声上做决策**。埋点修复是整个计划的前置条件。

## 3. 三条路径详述

### 路径 A｜保守：订阅深耕（Free → Pro $9 → Studio $29）

**做什么**：不改商业模式，只修漏斗与提价结构。
- 修 GA4 埋点（当前第 3 段 104.8%、第 6 段与 DB 不一致）
- 年付 $79 设为默认选项（把综合费率从 19.46% 降到 13.27%，首笔到账从 7 个月缩到 1 个月）
- 打开 Studio $29（含 API access、竞品对比、15 域），把 ARPU 天花板从 $9 抬到 $29
- 免费审计结果页加邮箱捕获，把 leads 从 0 变成资产

**单位经济**：LTV $72–$133（$9 月付）/ $330（Studio $29）。现金 CAC = 0。
访客成本 250/单，当前月流量 83 → 约 3 个月出 1 单。

**为什么现在不推荐**：需要 135–170 倍流量增长才到 $500 MRR。
14 天内唯一能验证的是「埋点是否修好」，**不是「收入是否跑通」**。
这条路径的胜负手在 SEO 排名（均排 69.1 → 前 10），而 SEO 是 3–6 个月周期，两周内不可验证。

### 路径 B｜激进：done-for-you 服务先行（推荐）

**做什么**：把 $49/$129 Fix Pack 从「订阅的附属品」升级为**主收入来源**。

**需求证据是站方自己挖出来的**（来源：https://geoscore.help/fixpack/ ，抓取 2026-10-27）：
- 站方 2026-10-23 亲自检查 20 家知名 DTC 商店的 llms.txt 与 robots.txt：
  **每一个 llms.txt 要么是 Shopify 空模板（零产品事实）、要么是 65 字节的坏文件、要么是 404**；
  robots.txt 从未提及 GPTBot / ClaudeBot / PerplexityBot。
- Visibility Mesh《State of AI Visibility 2026》（2026-06）：216 家 Shopify 店中位 AI 可见度 **46/100**，仅 13% 对 AI 爬虫完全可读。
- 站方自有样本：343 个站点中，得分 > 72 的 18 个站点**全部**有真实 llms.txt（自述为相关性，非因果）。

这是一条「已验证痛点 + 已验证人群 + 已有产品」的路径，缺的只是成交动线与归因。

**单位经济**：
- 客单价 $49（净 Fiverr $36–38 / 净站内 $46.69）→ $129（净 Fiverr $100–102 / 净站内 $123.57）→ $299 站点级
- 现金 CAC = $0（Fiverr 站内流量 + 自有免费审计引流）
- 1 单即回本，无需累积流量
- $500/月 = **11 单 $49**，或 **4 单 $129**
- 对比：1 单 Fix Pack（$49）≈ **5.4 个月的 Pro 订阅毛收入**，且不受 $50 提现门槛卡 7 个月

**工程量**：低。诊断表单 + 文案改写 + 交付 SOP，几乎不碰核心代码。

**🔴 但有一个必须先解决的价值主张错位**：
Fix Pack 页面自己承认（引用 Ahrefs 2026-06 对 137,210 个域名的服务器日志研究）：
**97% 的 llms.txt 在 2026 年 5 月收到零请求**，且没有主流 AI 厂商声明会读它，Google 明确说忽略。
也就是说，这个 $49 包名义上的核心交付物（llms.txt）**自己证明是无效的**。

> **必须执行的改写**：把 $49 的主承诺从「重建 llms.txt」改为
> **「robots.txt 爬虫准入 + Product Schema 完整化」**（这两项是机器可验证的），
> llms.txt 降级为「免费赠品」。否则卖的是自己都不信的东西，退款与拒付风险极高。

**失败信号**：14 天内 0 单；或 30 条有效线索 0 转化（说明痛点不够痛或人群选错）。

### 路径 C｜转型：B2B2B 白标 + API + 数据订阅

**做什么**：放弃散户，转向给代理商供货。
- Agency $59/mo（白标 PDF 报告，当前 "Coming Soon"）
- API 单独售卖（当前 Studio $29 档含 API access，未单独定价）
- 行业基准数据订阅：GeoScore 手上已有 324/343 站点的自有样本，这是别人没有的资产

**单位经济**：客单价 $59–$299，LTV $676（Agency $59 × 12 月，按 ARPU $50–100 档 8.4% 月流失）。
B2B SaaS 访客→线索 1.1%–2.5%（SaaS Goodies 2026）。

**为什么现在不推荐**：
- 工程量中高（白标 PDF、API key 管理、按量计费、团队工作区），两周内做不完
- 需要人工销售触达代理商，与当前「零投放 + 内容获客」的能力不匹配
- 验证周期 8–12 周，超出本次两周窗口
- **没有可验证的中间指标**：4 周内若 0 家代理商愿意预付，无法区分是「产品不对」还是「触达不够」

**但它是最有价值的长期期权**，建议作为路径 B 跑通后的第 2 阶段。

## 4. 推荐路径与取舍理由

### ✅ 推荐：路径 B（激进：done-for-you 服务先行）

**一句话描述**：
> 把 $49/$129 一次性 Fix Pack 做成主收入，用「免费诊断」表单把 leads 从 0 变成可培育资产，
> 新客借 Fiverr 的流量与 escrow 成交，复购导回站内 Creem 结账省 17%–21%；
> 同时用保守路径里两个零成本动作（修埋点、加年付默认）给订阅端供弹。

**为什么是它——用数字说话**：

| 判据 | 路径 A（订阅） | 路径 B（服务） |
|---|---|---|
| 达到 $500/月所需单位数 | **56 个活跃订阅** | **11 单 $49**（或 4 单 $129） |
| 所需流量 | 11,200–14,000 会话/月（**135–170×**） | 无需大流量，靠定向触达 |
| 首笔现金到账时间 | **7 个月**（$50 提现门槛卡住） | 1 单即可（Fiverr 14 天清算 / Creem 1 个月内） |
| 单笔毛收入 | $9 | $49（**5.4 倍**） |
| 14 天内可否验证成败 | ❌ 否（样本不足） | ✅ 是（0 单 / ≥3 单，二元可判） |

**核心逻辑**：在 83 会话/月的流量现实下，**唯一能产生现金的是高客单价、低成交频次的服务**。
订阅模式需要流量复利，而复利的起点是排名（均排 69.1），那是 3–6 个月的事。
先靠服务活下来并拿到真实付费信号，再拿这些信号反哺订阅与内容。

### ❌ 为什么不选路径 A（保守）作为主线

不是因为它错，而是因为它**在两周内不可证伪**。
修埋点、加年付、开 Studio 都是**必须做的**（已并入 B 的支撑动作清单），
但它们是「让订阅将来能跑」的地基，不是「这两周能出钱」的引擎。
把主线押在 A 上，两周后的产出会是「埋点修好了」而不是「收到钱了」。

### ❌ 为什么不选路径 C（转型）作为主线

工程量超出两周窗口，且需要销售能力（当前为零）。
更关键的是它**没有可证伪的中间指标**：若 4 周 0 家代理商响应，无法区分
「产品不对」「触达不够」还是「人群根本不存在」——这是最坏的一种失败，因为学不到东西。
保留为路径 B 跑通后的第二阶段。

## 7. 风险与合规提示

### 7.1 Creem 作为收款方（MoR）

**已核实（第一方来源）**：3.9% + $0.40/笔；$0 月费/开户费；每月 1 日、15 日提现；
余额门槛 $50；风控冻结 7–12 天；覆盖 190+ 国家税务（GeoScore 定价页 FAQ 亦如此声明）。

**风险（第三方评测，Payment Review 2026-10，https://paymentreview.com/comparisons/creem-vs-lemon-squeezy）**：
- Creem 由 **Armitage Labs OÜ**（爱沙尼亚塔林，2024-04 注册）运营，**公司很年轻**
- **每个店铺上线前都要审核**，有较长的禁止清单，**可在宽泛条款下扣留资金**
- **Trustpilot 约一半是一星评价**，多数来自被拒、被封号、被冻结资金的商户
- 银行提现 **$7 或 1% 取高**、USDC 提现 2%、**拒付 $25/€25 每笔**

**对 GeoScore 的具体影响**：
- 单点依赖风险：Creem 若封号/冻结，$9 MRR 与 $49 收入同时中断 → **必须准备备用通道**（动作清单 D10）
- 拒付风险：$49 服务类（done-for-you）的拒付率**天然高于订阅**。
  每笔拒付 $25，相当于一单 $49 的一半毛利 → **必须在成交前用书面形式锁定交付范围（scope）**，
  并优先用 Fiverr escrow（买家先验货后放款）
- ⚠️ **$50 提现门槛 × $9 客单价的组合是致命的**（首笔到账 7 个月，综合费率 19.46%）。
  这是本方案把「年付 $79」列为必做动作的唯一原因

### 7.2 税务

- Creem 作为 **Merchant of Record**，负责其作为法律卖家的那部分交易税（VAT/GST/销售税）的
  计算、征收、申报与缴纳（https://creem.io/blog/eu-vat-vida-2026-saas-compliance-guide）
- **但卖家自身的企业所得税 / 个人所得税、以及 Creem 安排之外的销售，仍需自行申报**
- **本文档不提供税务建议，也不承诺代办**。相关登记、申报、缴税需用户本人在
  税务机关或委托的持牌税务顾问处完成。不同司法辖区（尤其中国境内主体 + 境外收款）
  的规则差异很大，需自行确认

### 7.3 Fiverr 站外成交的归因盲区（🔴 最需要警惕的一条）

- **GA4 完全看不到 Fiverr 上的成交**：跨域跳转、Fiverr 常处于登录态/App 内、
  无 referral 回传 → **leads = 0 不等于「没需求」，很可能是「没埋点」**
- 这直接导致：**无法计算 Fix Pack 的真实转化率、无法做归因、无法优化**
- **对策**：站内诊断表单是唯一可信的线索真源，所有外部引流（Fiverr / 社群 / 邮件）
  **必须全部导向站内表单**，不得让成交只发生在 Fiverr 内部
- **品牌一致性风险**：Fiverr 账号名为 `chinesefood885`，与品牌 `GeoScore` 完全无关。
  买家从 geoscore.help 跳到一个名为 chinesefood885 的 Fiverr 账号付款，**信任断层**，
  这会直接压低成交率。建议尽快更换为品牌一致的账号名（需用户在 Fiverr 平台自行操作）

### 7.4 退款与交付

- Creem 拒付 $25/笔。done-for-you 服务的拒付争议点通常是「效果未达预期」
- **对策**：交付物必须是**机器可验证的**（robots.txt 爬虫规则、Schema 校验通过），
  **绝不承诺排名或 AI 引用**（站方 Fix Pack 页面已正确声明「不保证排名或引用」，应保持）
- 站方已在页面引用 Ahrefs 2026-06 研究（137,210 域名，97% 的 llms.txt 零请求）
  并明确「不把 llms.txt 当作引用杠杆来卖」——**这个诚实做法应保留并强化，
  但必须同步调整商品主承诺，否则卖的是自己证明无效的东西**

### 7.5 其他

- **定价页与首页矛盾**：首页 FAQ 称提供 Pro/Studio/Agency，定价页 Studio/Agency 全为 "Coming Soon"。
  属于「标价但买不了」，是转化杀手，也容易被 AI 抓取后生成错误答案
- **$9/mo 的定位问题（⚠️ 本条已于 §11 修正，以下为被推翻的初版判断，保留以存痕迹）**：
  初版依据二手聚合页认为「$9 在赛道内可行，同价位有 BotView $9 与 AEO Vision Lite $9 在售，
  且我们的包含量并不寒酸」。经 competitor-analyst 一手核价后**此判断部分被推翻**：
  ① AEO Vision 已停运（域名挂牌出售）；② BotView $9 给的是**真实**调用而我们给的是**模拟**。
  **修正后的结论见 §11.2：$9 是赛道孤例且我们在该档位的价值最弱，建议提价至 $19–29。**

## 12. 第三次修订（成本模型方法论更正）

> competitor-analyst 核清了我在 §10.1 / §11.1 标注为「存疑」的那条，**发现我的推导有方法论错误**。
> **本节第二次推翻 §10.1/§11.1 的部分结论。结论方向仍成立，但支撑理由必须换——

### 12.1 🔴 我的方法论错误：把「竞品公开售价」当成了「行业成本」

**错误的根源有两个**：

1. **$0.0087–$0.08/次 那组数字，是竞品的公开售价，不是行业真实成本。**
   我用它反推「各档位能买多少次」，本质是在算「按零售价能买多少」，不是「边际成本是多少」。
2. **更要命的是：AI 引擎查询有两条成本模型完全不同的技术路线，我当成了一条。**

| | **路线 A：真实 web 界面自动化** | **路线 B：LLM API + web search** |
|---|---|---|
| 谁在用 | **Otterly**（官网原话：*"Real web-interface monitoring... queries the actual AI search interfaces the way a human user does, **rather than hitting an API endpoint**"*）；Scrunch（混合） | **BotView**（明说 OpenAI API + web search）；Otterly 的 Claude 加购（*"uses **Haiku** through the API with web search. This does not measure Sonnet, Opus or the consumer Claude app."*） |
| 计费方式 | **不按 token**。成本 = 服务器 + 代理 IP + 浏览器自动化的**固定基础设施摊销** | **按 token 线性可变**，但可挑便宜模型压低 |
| 边际成本 | **规模化后趋近于零** | 恒定为单次单价 |
| 拿到的数据 | 真实引用与链接位置 | 模型文本（非真实引用位置） |

**所以我那条「Otterly $29 只负担得起 412 次却给了 1,800 次，说明它在亏钱引流」是错的。**
正确答案：**Otterly 走路线 A，其边际成本不遵循 API 单价模型，1,800 次/月不构成亏损证据。**

### 12.2 ✅ 修正后的正确表述（请用这一版）

**最终核心结论（替换 §10.1 / §11.1 的结论）**：

> **$9 不是「成本锁死」，是「规模锁死」。**
> 真正的约束是 **83 会话/月**，不是价格。
> 在当前规模下，两条真实查询路线都不划算：
> - 路线 A（web 自动化）：固定基础设施投入无法被 83 会话/月摊销
> - 路线 B（API）：低量级给得起（20 次/月仅占净收 2%–19%），但**监测级量给不起**
>
> **这个理由比原版更硬**：原版（算术版）会被「Otterly 反例」一击即破；
> 新版把约束从「价格」改回「规模」，**与本报告的核心结论（卡点在「没人来」）完全自洽**。

⚠️ **§10.1 那张「各档位可负担查询数」表需重新解读**：
表中的「124 / 412 / 1,055 次」应理解为「**按 API 零售价能买到的次数**」，
**不是「真实边际成本能支撑的次数」**。路线 A 下这些数字不成立。

### 12.3 🆕 由此得到的一条工程指导（新结论）

### 15.3 成本口径对账：我的 $0.40–1.80 与 oss-analyst 的 $4.8–7.8 不矛盾

初看打架，核算后确认**是同一事实的两个切面，差别在采样量而非单价**：

| | oss-analyst（实测） | 本报告（零售价代理） |
|---|---|---|
| 采样量假设 | **600 samples/月**（≈20 次/天，**监测级**） | **20–90 次/月**（**抽查级**） |
| 月成本 | $4.8–7.8 | $0.40–1.80 |
| **反推单价** | **≈$0.01/sample** | $0.02/sample（**比实测高 2 倍**） |

→ **单价上 oss-analyst 比我准**（他是实测，我是零售价代理）。
**差额全部来自「每用户每月跑多少次」**，而这正落在 §12 的结论上：
**$9 给得起抽查级，给不起监测级。两侧独立走到同一条线。**

**交集解（采纳）**：低价档采样量锁 **≤200 samples/月**（oss-analyst 口径 ≈$2/月）

| 档位 | 净收 | 200 samples 成本 | 占比 | 毛利 |
|---|---|---|---|---|
| $9 | $8.25 | ≈$2.00 | 24% | $6.25（薄但为正） |
| **$19** | **$17.86** | ≈$2.00 | **11%** | **$15.86** ✅ |

→ **$19 + ≤200 samples/月 = 两组数据的交集解**（更新 §13.6 的配置）

### 15.4 🔴 前置硬约束：付费档能力 < 自托管免费档（我此前不知道）

oss-analyst 从 OSS 侧实测确认（与 site-health-auditor 的发现相互印证）：

> 自托管 CLI/MCP 用户**可自行更换 LLM 端点**（`LLM_URL` + `env.TOKENRHYTHM_API_KEY`），
> 而 Pro 档 `worker/pro.js` **无 API key 体系**。
> ⇒ **免费的那个版本比付费版本更开放。**

**这条直接卡住我 §11.2 / §13.6 的全部涨价与加档位方案**：
我建议了「$19 + 90 次真实查询 + 10 域名」以及「开 Studio $29（含 API access）」——
**若付费档连 API key 都没有，这些加了也卖不动：付费档能力倒挂于自托管免费版，涨价只会加速流失。**

> **新增前置条件（插入 D11 之前）**：
> **任何涨价 / 加档位动作，必须先修复「付费档能力 < 自托管免费档」这个倒挂。**
> 这是 §13.9 所有订阅侧动作的**闸门**，不修则后续全部不成立。

### 15.5 价格带下端是 $0——而且是我们自己的 $0

oss-analyst：赛道下端是 elmo 自托管档（MIT）"unlimited prompts, every supported engine — Free"，
Cloud $29/mo；niubigeo 开源自托管 + 卖 ¥99/份报告。

**我补一层更对称的表述**：**GeoScore 自己也是 MIT + CLI + MCP**，
即**我们自己的免费档同样是「$0 自托管」**。

→ 准确说法不是「我们 $9 面对竞品的 $0」，而是 **「我们的 $9 面对我们自己的 $0」**。

**对定价结论的收紧**：
> **付费档的价值锚 = 运维外包 + 定时监测 + 历史 + 告警 + 多域，
> 而不是「能用」这个能力本身。** 任何卖点在自托管版也能获得的，都不构成付费理由。

这也解释了 §13.1 的计价轴问题为何更严重：域名数既不是真实的价值变量，
又无法与「自托管免费版」拉开距离——**两头都不占**。
