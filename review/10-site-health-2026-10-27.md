### 1.4 ⭐ 核心核实：有没有任何功能真的去查询 AI 引擎并保存原始回答？

**答：没有。06 号审计的结论依然成立，未被推翻。**

证据链（本次实跑）：

1. **全仓 grep 引擎 API 域名**
   `grep -iE 'api\.openai|api\.anthropic|perplexity\.ai|generativelanguage|api\.x\.ai|groq'`
   → 全仓仅 2 处命中，且都是**文本不是调用**：
   - `data/geo-corpus.csv`（语料数据）
   - `src/pages/blog/geo-tracking-ai-visibility.astro`（博客正文）

2. **「AI 可见度」的真实实现**（`worker/visibility.js`）
   - 第 5-13 行文件头自己写明：
     > "AI recommendation simulation" … **"Transparency: this is a simulation based on public site content, NOT a measurement of real AI engine traffic."**
   - 第 19-20 行，实际调用的是：
     ```js
     const LLM_URL = 'https://tokenrhythm.studio/v1/chat/completions';
     const LLM_MODEL = 'deepseek-v4-flash-0731';
     ```
   - 第 30-35 行：给 deepseek 套 4 个「人格 prompt」（ChatGPT / Perplexity / Claude / Gemini），让它**扮演**这四个引擎回答。
   - 输入只有目标站首页的 title + meta description + 正文前 1200 字符（`visibility.js:73-99`）。

3. **原始回答确实保存了，但保存的是「模拟模型的输出」**
   - `visibility.js:170` `raw: content.slice(0, 2000)`
   - `visibility.js:182-184` 写入 D1 `ai_visibility.raw`
   → 所以「保存原始回答」这个动作**有**，但内容是 deepseek 的模拟答案，**不是**任何 AI 引擎的真实回答。
   这是本条核实里唯一需要精确表达的差别，请不要在下游文档里简化成「有保存原始回答」。

4. **前端/后端都没有第二个路径**：`worker/visibility.js` 是唯一的可见度实现，`freeVisibility.js` 与 `pro.js` 都只是它的调用方。
