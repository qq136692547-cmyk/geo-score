# GeoScore 标杆化诊断与改造路线图

诊断日期：2026-10-22/23 · 方法：5 个专项并行体检（数据可信度 / 设计系统 / 关键词 / 内链 / 转化）+ 主理人裁决 · 全部结论带文件行号或复现命令

---

## TL;DR

1. **产品本身有硬资产**：11 维审计、robots 按 RFC 9309 解析、同 URL 三次跑 94/94/94 的确定性、以及 `data/STUDY.md` 里主动撤回假数据的记录。
2. **但有七处 P0 级事实错误**，其中两处会**伤害用户的站**（生成的 robots.txt 会解锁故意禁止的站；生成的 JSON-LD 过不了自己的检查）。
3. **对外有三套互斥的分数分档**，两个公开页面互相打脸；45.7% 的展示押在一个语义错配的词族上。
4. **最大缺口是流量**（1219 展示 / 2 点击 / 真人 14 pv/11 天），**最大风险不是流量，是"用了工具反而更差"**。

### 1.2 设计系统（蓝本之）

- **三套分档并存**：`scoring.js` 36/68/86 · 3 个 UI 组件 40/60/80 · 研究文章 40/70/86。文章印的 144/152/28/0 **只有 40/70/86 能复现**。

- **Token 空转**：`@theme` 45 个 token 里 8 个死、13 个只被自己引用；页面实际用裸工具类（`bg-white/5` 282 次）。缺圆角/间距/容器/阴影/字号 token。

### 1.3 关键词（关宇霖）

- **45.7% 的展示押在打不动的词上**：工具页 619 展示 / 均排 78.6 / 1 点击。实查 `ai readiness score` SERP 前 5 **全是企业 AI 成熟度咨询**（lsbuk / complyjet / intuz / ecosmob / aidolsgroup），与"网页技术层能否被 LLM 引用"不是同一语义。
- **展示在收缩但排名在改善**：28 天展示占 90 天的 23%，均排 67.3 → 47.7。
- **需求是任务型，供给偏教育型**：排得最好的 7 个词全是带场景的完整问句（均排 2–11）；13 篇文章有 7 篇零展示，包括最对症的两篇。
- **竞品四类生态**：`ai readiness score` 被咨询公司占死（不打）；`geo audit tool` 被 geoaud.it 占 4/5；**`llms.txt checker` 唯一可撬动**；`how to get cited by chatgpt` 无工具商占位。

### 1.4 内链（连乐桥）

- **孤岛页 0 个**（36 可索引页与 sitemap 一致）。
- **77.1% 的内链是页脚/导航样板**（931 条里 718 条），正文链接仅 213 条（5.8 条/页）。
- **三条方向为 0**：tool→blog = 0 · methodology 收 52 条入链、正文出链 0 · 中文 11 页与正文网完全隔离。
- **`/pricing/` 只有 2 条正文入链，15 篇博客零引用** —— 用户读完全部文章，站内没有任何一处告诉他"有付费版"。
- **尾部发现**：`/blog/llms-txt-ultimate-guide/` 里 `Run free llms.txt audit →` 的 `href` 是 `/`（首页），另有一条链接指向自己。

### 1.5 转化（率可成）

**⚠️ 先纠正一条口径**：`90 天 0 次 upgrade_cta_clicked` **不能当"没人想买"的证据**。
它要穿过 5 道门才被记录，其中一道是"接受 analytics"——`consent.js:170-176` 两个勾选框默认不勾，
点 "Essential only" 或 "Save choices" 就永不上报（`Layout.astro:73-79`：`geoTrack` 只在 `gtag` 存在时生效）。
14 次会话 × 0.4 × 0.6 × 0.5 ≈ **1.7 次可被记录的期望值**，观测到 0 在噪声内。

> 正确表述：**0 次是"没人走到那儿"的弱证据，不是"走到也不买"的证据。**

**七个断点**：

|---|---|---|
| **C1** | **结果页没有"下一步"，且付款请求排在待办之前** | `boot.js:400` 的 CTA 是第 5 块、`:404` 的修复清单是第 9 块；94 分走 "你很好→但你无法证明→所以买"（`upgradeCta.js:57-63`）；`reportHeader.js:11-31` 整个分数头无动作元素 |

⇒ **现阶段唯一值得做的 CRO 是把 aha 提到免费端（C5 的反面），不是调按钮。**

## 二·五、分档判据与两条自我约束

**分档的判据是「前提个数」，不是「确定性」**：0 个前提 = **A 档**；1 个前提（站内权重可传递） = **B 档**；2 个以上 = **C 档**。
同一个档位内部强度也不等——例如 C3 里只有两对"强配对"（eeat 22.4 → geo-citation、llms-txt 49.5 → ai-crawler），另两对属中偏低。
**每个数字还应带来源标签**（GSC 实测 / 源码实测 / 重算 / 推断）——本轮四个成员共错了 9 处，几乎全部是"把推断当事实"。

---


**1. "改完即改善"只适用于属性与文本错误** —— href 写错、锚文本与落点不符、301 缺失。
"补一条看起来很合理的链接"**全部是有前提的主张**，前提是"站内权重传递对排名有效"。
**判断标准是证据强度（要不要做假设），不是成本高低（麻不麻烦）。**

**2. 任何"引用不利证据来建立可信度"的动作，先问自己是否正在做相反的事。**
- 想引 "97% 的 llms.txt 零请求" 来立可信度，但产品给 llms.txt **12% 权重**、"文件存在"还白送 4 分
  → **引了不改就是自证矛盾**（必须先做 A11）
- 想讲 E-E-A-T，但 `eeat.js` 用正则判信任页、`brand.js` 用一个 `@` 判联系方式
- 这条适用于所有"承认局限"类文案——**诚实必须与实现一致，否则诚实反而是破绽**

**3. 展示量不等于权重，也不等于新增。** 要落到**词级归属**和**均排**。
- `/about/` 56 展示 → 是品牌落点，不是内容源
- `/blog/what-is-geo/` 130 展示 → 泛词页、均排 83.8，不该当链接源（反例：`eeat-signals` 只有 30 展示但均排 22.4）
- 德语 62 展示 → 是**转移**，不是净增

> 三条防的是同一个错误：**拿一个容易拿到的聚合数字，代替需要多查一步的事实。**

## 三、不可抄 vs 可抄

**不可抄（真护城河）**
1. `data/STUDY.md` 主动撤回假数据并复算 —— 记录错误的勇气，竞品不会做
2. robots 按 RFC 9309 解析的严谨度
3. 同一 URL 三次跑给同一个分数（确定性）

**可抄（一个周末就能被搬走）**
UI 风格、页面结构、llms.txt 生成器、11 维命名体系 —— **都不构成壁垒**。
